# AI Usage

This assignment was built with **Claude Code** (Anthropic, Sonnet 5 model) end-to-end,
working interactively in this repo.

## What it was used for

- **Spec authoring** — `PRODUCT_SPEC.md`, `TECH_SPEC.md`, `DECISIONS.md`, and `PLAN.md`
  were drafted with Claude Code, resolving ambiguities in the original brief into concrete,
  numbered decisions before any code was written.
- **Implementation** — every commit in the git history following the scaffolding commits
  was generated by Claude Code, executing `PLAN.md` step by step: backend (Express routes,
  sqlite repository, validation), frontend (Pinia stores, composables, router, shadcn-vue
  based screens), and the two test files.
- **Verification per step** — after each step, Claude Code ran the relevant typecheck/build
  (`vue-tsc`/`tsc`), and for the backend, started the server and exercised the four
  `/api/users` endpoints with `curl` to confirm status codes and payloads before committing.
- **Manual QA pass** — a pass against the product spec's edge cases (fetch-once semantics,
  saved-flag persistence, full-reload-resets-to-Home) surfaced one real bug: `vue-router`'s
  `createWebHistory` would restore whatever route was in the URL bar on reload instead of
  resetting to Screen 0. Fixed by switching to `createMemoryHistory`.

## What it was not used for

Browser-based visual verification was attempted but the Chrome extension used for that was
not available in this environment, so the UI was not visually inspected by the assistant —
only typechecked, built, and reasoned through against the product spec. A human should give
the running app a visual pass before treating this as done.
